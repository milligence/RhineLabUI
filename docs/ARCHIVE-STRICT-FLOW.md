# 档案流程：本轮设计与复现

本文记录入场、启封、投影的设计约束，以及公开占位集合的复现方法。它不是验收报告，不包含实际通过结论。状态检查、真实场景关键帧和正常网页操作分别提供不同证据，不能互相替代。

## 1. 自然入场：阵列只形成一次

普通网页的阵列入场使用 `webArrayArrival`，时间从开场时钟的 `21.92 s` 到 `25.9 s`。此前的二维开场继续使用既有时间轴。

入场从可辨识的斜俯视角开始，白幕逐渐退出，阵列形成原有交互波场，选中的档案抬升到预览位置。镜头、轨道和波场在结束时落到交互初态。内容只有两列时，也按实际选档所在轨道进入，不借用参考影片的第三列位置再归位。

白幕填满它实际所属的自适应背景容器。它不是中央 1920×1080 图形层的子节点，不能再次施加中央图形的居中补偿；否则非16:9窗口会在左侧或上方露出色带。流程检查页也设置与主页面一致的开场尺寸变量，避免缺少变量反而让错误规则失效、掩盖生产页面问题。

自然入场不使用参考影片的两次波包，也不显示随后会换位的临时影片 callout。档案操作区域在进入交互布局后出现。阵列结束时保持封存状态，读取或投影都需要用户选择。

品牌标题在阵列入场进度的 `32%—92%` 内，按同一进度逐渐收束到最终响应式布局的位置和尺寸。紧凑布局中即将隐藏的 `POWERED BY` 同期淡出。这样，`openingLayout` 切到 `viewportLayout` 时，品牌不再依赖一次突然的坐标切换。此调整只作用于自然网页入场；参考影片的品牌位置保持原样。

GPU 首次编译或慢帧不能吞掉整个揭幕段。自然入场通过校正已有 `bootStart`，将此段每个实际帧的推进限制为最多 `50 ms`。二维幕、开场音效触发和三维姿态仍读取同一个开场时间；这项处理不代表提高了渲染帧率。

主要实现：

- `src/archive-arrival.ts`：自然入场进度与纸张状态。
- `src/boot.ts`、`src/archive-entry.css`：二维揭幕及品牌布局交接。
- `src/main.ts`：自然入场路由、共用时钟及交互入口。
- `src/scene.ts`：真实相机、轨道、波场与实体姿态。

### 参考影片与显式播放

未指定 `arrival=web` 的显式时间查询、参考冻结，以及 Wallpaper 的影片播放继续使用参考镜头和波场。自然网页结束于阵列的规则不代替 Wallpaper 明确选择的完整播放。

参考影片处于 `boot` 模式时，DOM 正文纸页原本就不显示；扫描与玻璃启封由参考时间驱动。显式完整影片已经解密后进入 `detail`，沿用已完成的纸页状态，不重新等待一轮启封。普通网页读取与未完成的影片跳转仍使用下面的物理门槛。

## 2. 启封：纸张等待实体与镜头

档案本体保持竖直抽取。左右构图与靠近由相机完成，不平移实体到阅读位置，也不让邻档额外下沉腾出空间。

正文容器可以先提供返回操作，纸面本身需要同时满足两类状态：

| 状态 | 判定依据 |
| --- | --- |
| 实体与镜头就位 | 抽取接近完成、邻档净空足够、相机进入阅读构图，实际位置与目标位置的残差收敛 |
| 当前启封进入揭示阶段 | 当前解密时间轴进入 `revealing` 或 `clear`，玻璃开始变清；不能仅凭上一次残留的透明度放行 |

两项满足后，纸面用 `1.1 s` 渐现，并完成短距离的上移。它不是点击后固定等待一个短计时器便弹出的整张不透明纸。

文字遮盖在纸面实际可见后才开始退出，避免文字揭示过程在隐藏纸面上提前耗尽。重新打开一份档案时，先清空上一轮纸面的内联透明度。关闭、重新选择和中途反向都从当前物理状态继续；关闭后再打开会重新检查当前启封阶段。

减少动态效果时可以省略纸面的渐现，但仍须满足相应状态。模型解密与文字揭示的独立设置继续生效。

### 只读状态

正常网页的 `window.rhine.stats()` 包含下列状态，供记录实际进度：

| 字段 | 含义 |
| --- | --- |
| `mode` | 当前网页路由 |
| `arrival` | 自然入场或参考播放的类型、进度与阶段 |
| `documentArrival.ready` | 实体及普通阅读相机是否就位 |
| `documentArrival.clear` | 当前启封是否允许纸面揭示 |
| `documentArrival.progress` / `visibility` | 纸面进度与实际淡入系数 |
| `documentArrival.phase` | 抽取、启封、纸面揭示、可见或关闭阶段 |
| `documentArrival.cameraResidual` | 实际普通相机相对目标构图的归一化残差 |
| `paperReady` / `paperVisibility` | 便于检查台直接读取的纸面状态 |
| `projectionReady` | 实体及镜头是否已经可以开始投影 |

`reference` 完整播放已经解密的交接是继承状态；检查普通网页的新启封门槛时，应使用自然网页入口或公开流程页。

## 3. 投影：先看清来源，再接管视角

档案是投影来源。研究树与 Cube 使用同一套载体过场，入口从实体档案的实际孔径位置采样。

一次完整投影开启的名义呈现时长为 `5.2 s`，从载体准备好、投影开始计时。此前的实体抽取不计入这 `5.2 s`。开启过程按以下关系组织：

1. **源点亮。** 档案上的孔径先蓄光，提供可辨识的来源。
2. **光束生长。** 光体从孔径伸向成像区域，再逐渐展开，不能用完整三角形突然变亮代替生长。
3. **影像形成。** 边框与扫描共同建立像面，研究树或格阵随揭示范围出现。
4. **成像停驻。** 保留短暂的完整像面，让人看清档案、光束与影像的关系。
5. **相机接管。** 视角再进入影像，环境、标题和交互控件随之展开；实体按真实镜头关系退出画面。

`carrier-flight.ts` 提供共用的光学路径和节奏，`projection-viewer.ts` 负责像面与光束的绘制。投影层使用实际相机已更新的相位，减少 DOM 像面与三维载体分别运行时出现的错帧。过场中的反向关闭保留当前运动状态，再减速返回。

呈现时钟限制单个慢帧的推进，隐藏标签页不继续消耗开启过程。因此低帧率环境中的实际墙钟时间可能长于 `5.2 s`；不能据名义时长宣称某台机器已经流畅运行。

从已打开的正文进入投影时，纸面在蓄光阶段用 `340 ms` 退出，返回正文时用 `420 ms` 恢复；这一路径保留原有正文和滚动位置。从阵列直接进入投影则保持纸面隐藏。两条路径通过 `projectionRoute` 区分，避免把直接投影误做成先弹出正文。

### 坐标边界与 QA 页修正

生产 `main.ts` 从一开始就将 `ProjectionViewer` 挂在 **未缩放的 `#viewport`**。带 `transform: scale(...)` 的 `#stage` 是它的子层，生产投影层不继承这层缩放。

旧 QA 页面曾将 `ProjectionViewer` 挂到缩放后的 `#stage`，把屏幕坐标与 stage 内部坐标混用，导致该 QA 页的源点、光束和影像位置失配。不能把这次 QA 挂载错误写成生产 `main` 原有的缩放缺陷。当前流程页与阅读页都采用 `#viewport` 挂载。

绘制器同时增加了通用的 `carrierLocalPoint` 转换：把屏幕 CSS 像素按容器实际边界换算到容器内部尺寸，孔径、SVG 光束和像面使用同一坐标空间。该修正提高绘制器面对缩放宿主的健壮性；生产入口与 QA 挂载问题应分别描述。

## 4. 构建五组、每组十份的公开复现包

在仓库根目录安装依赖后运行：

```bash
npm run review:collection
```

该命令先生成 `content/fixtures/array-5x10.json`，再通过隔离构建生成复现包。五组共五十份内容均为公开虚构占位记录，不导入个人研究正文，也不覆盖生产目录中的档案集合。

每组第一份包含研究树投影，第五份包含可交互 Cube；其余样本用于检查普通记录、长标题、长正文及首尾切换。构建输出同时保留正常网页和审核入口。

构建结束会输出实际目录，例如：

```text
Private archive ready: /完整仓库路径/.private-build/archive-随机后缀/dist
```

这里沿用隔离构建工具的输出名称；本命令输入的是公开占位集合。复现时使用本次输出的准确 `dist` 路径。

生成目录包含：

| 相对输出路径 | 用途 |
| --- | --- |
| `index.html` | 正常 `main.ts` 网页，核对实际入口、路由、焦点及操作 |
| `reference/archive-flow-review.html` | 实际档案场景的固定步进、关键帧与五十份状态巡检 |
| `reference/archive-reading-review.html` | 正文及研究树文字层次的静态检查 |

`prepare-flow-review.mjs` 从生产 `main.ts` 提取 stage 与正文模板，构建审核页使用的生成模块。不要手工修改生成模板来制造独立于生产页面的表现。

## 5. 启动复现服务器并保存检查数据

将 `REVIEW_DIST` 改为上一条命令输出的实际目录：

```bash
REVIEW_DIST="/完整仓库路径/.private-build/archive-随机后缀/dist"
python3 scripts/serve-flow-review.py "$REVIEW_DIST" \
  --port 5195 \
  --report "/检查输出目录/archive-flow-review.json"
```

服务器只监听 `127.0.0.1`。打开：

- `http://127.0.0.1:5195/`：正常网页。
- `http://127.0.0.1:5195/reference/archive-flow-review.html`：流程检查台。
- `http://127.0.0.1:5195/reference/archive-reading-review.html`：文字与静态布局检查。

`--report` 必填。检查台点击“导出检查数据”时，将 JSON 发送到 `/review-report`，服务器写入指定文件；它不会因页面载入而自动保存结论。若使用普通静态服务器，检查台可退回浏览器下载 JSON。

### 流程检查台

使用“自然入场”“启封”“收回”“投影开启”“收束投影”和步进按钮观察同一流程。`+0.1 s` 适合检查首次出现与遮挡交界，较大的步长用于移动到相邻阶段。`H` 可以收起或展开工具栏。

“50 份状态巡检”检查五组数量、选择身份、纸面门槛、读取完成与归位，并检查各组首尾循环和不同时间点中断后重新开启。报告保存检查条目、失败条目与已记录检查点的场景/投影状态。数据中的“通过”仅属于对应的状态断言。

巡检驱动器与生产 `main.ts` 的完整路由不是同一个入口。正常网页仍需独立检查切换列、打开/收起、读取与投影返回、键盘与焦点，以及视口变化后的操作位置。

## 6. 固定 60 Hz 积分与真实关键帧的区别

流程页实例化实际 `ArchiveScene`、`ProjectionViewer` 和档案 GLB。它以 `1/60 s` 为步长积分实际状态，在需要观察的检查点再绘制一次真实场景。

```ts
scene.update(simulationTime, cinematic, false); // 更新实际状态，不绘制
scene.update(simulationTime, cinematic, true);  // 在当前时间绘制检查点
```

`draw=false` 保留相机、实体、解密、实例矩阵、材质参数与可见性更新，在渲染缓存记录之前返回；同一时间戳的再次绘制不会额外推进一帧。自然入场共用 `webArrayArrival`，投影使用自身的手动呈现接口，没有另做简化卡片或伪造透视。

此方式适合在软件渲染较慢时逐帧检查形状、来源、遮挡和衔接。它**不证明实际运行达到 60 FPS**，也不代替连续播放中的节奏观察。审核页使用性能画质以降低检查点绘制成本；正式页面的目标画质仍需单独观察。

需要区分三类证据：

| 证据 | 能回答的问题 | 不能单独证明的内容 |
| --- | --- | --- |
| 固定步进状态轨迹 | 状态顺序、物理门槛、身份一致性、反向与首尾循环 | 画面是否好看、实时帧率 |
| 实际 GLB 关键帧 | 载体姿态、相机透视、光束来源、纸面遮挡、布局边界 | 帧与帧之间在目标设备上是否流畅 |
| 正常网页连续操作 | 实际路由、操作节奏、焦点、交互衔接与运行表现 | 尚未覆盖的全部视口或硬件情况 |

### 自然网页与参考影片冻结

正常网页可以显式选择自然入场的冻结检查：

```text
/?arrival=web&review=1&freeze=1&time=21.92
```

同源审核父页可以发送已有的 `rhine-review-frame` 消息修改时间。该查询明确选择自然网页时间轴；不加 `arrival=web` 的原参考冻结保持影片含义。流程页的“自然入场”按钮只从阵列揭幕段开始，完整二维开场与进入阵列的连接仍应在正常入口观察。

## 7. 阅读页的适用范围

`archive-reading-review.html` 使用当前正文模板和实际研究树模块，适合冷读概括、逐章检查故事、观察字数密度、换行、标题层级，以及节点中的当时记录、事后复盘和依据。

该页直接展示正文，研究树使用减少动态效果入口；它没有档案载体的完整抽取与投影开启过程。因此阅读页截图不能证明实体抽取、纸面时序、投影来源或相机接管动画正确。相关结论必须回到正常网页或实际场景流程页取得证据。

纯代码检查可另运行：

```bash
npx tsc --noEmit
npm run check:projection
```

这些命令检查类型、时间曲线和路由状态等约束。实际画面及连续流程的观察结果应另行记录，不填写在本设计与复现说明中。
