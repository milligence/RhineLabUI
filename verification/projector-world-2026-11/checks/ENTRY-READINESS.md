# 投影入口等待时间：原生方程数值核查

本记录核查新版入口门槛是否出现额外长尾。未修改任何生产阈值。

这是原生交互方程的数值运行，不是浏览器实测时延，也不代表视觉验收。默认起点是已稳定的阵列：选中轨道、肩部、视野、指针均已稳定；没有残留选档波、静止呼吸位移或 GPU 卡顿。模型只按原有规则竖直抽取。读取入口则从已稳定的详情镜头开始。

## 复现

```sh
node --experimental-strip-types verification/projector-world-2026-11/checks/entry-readiness.mjs
```

脚本生成同目录 `entry-readiness.json`。可加 `--trace` 把每个积分帧的完整轨迹另写入 `.tools/entry-readiness-full-trace.json`。

脚本直接提取并执行生产 `ArchiveScene.physicalProjector()` 与 `projectionEntryReady()`，并导入生产 `damp`、`smooth`、`settlingWave`、`archiveFraming` 与 `PROJECTOR_APERTURE`。相机目标、详情阻尼及相机跟随使用 `ArchiveScene.update()` 中现有方程；没有加入另一条投影预备动画。它也保留了真实更新次序：门槛读取上一张已呈现画面的相机速度，然后当前帧才测量新的速度。

## 60 Hz 主要结果

| 入口 | 1920 × 1080 | 390 × 780 | 最后放行的条件 |
|---|---:|---:|---|
| 默认阵列，原生详情动效开启 | 3366.667 ms | 3083.333 ms | 横屏：相机目标残差；竖屏：目标残差与 FOV 速度 |
| 已稳定读取，中性观察角 | 16.667 ms | 16.667 ms | 下一帧检查即通过 |
| 已稳定读取，原生合法最大拖转 ±0.8 rad | 2150.000 ms | 2150.000 ms | 旋转绝对值小于 0.002 rad |
| 已稳定读取，程序设置 180° 的压力样本 | 2633.333 ms | 2633.333 ms | 旋转绝对值小于 0.002 rad |
| 阵列，关闭 detailTransition、保留投影动效 | 350.000 ms | 333.333 ms | 相机速度／FOV 速度 |
| 读取，±0.8 rad，关闭 detailTransition | 183.333 ms | 183.333 ms | 旋转归正 |

**180° 不是正常读取拖拽可以到达的姿态。** 生产输入将档案拖转限制在 ±0.8 rad，约 ±45.8°。180° 只检验程序性姿态恢复的极端情况，不能写成正常用户需要等待的默认时间。

这些数值是 `projectionReady` 首次通过的积分帧。真实主线程 RAF 排队可能增加一个呈现帧；资源准备、GPU 卡顿和后台节流不包含在表内。原生场景的每步 `dt` 上限以及演出时钟的停顿保护意味着严重卡顿时，实际墙钟时间可能更长。

## 默认阵列：端口进入画面与正式接管不同

端口在已稳定的预览起点已经在画面内。开始抽取约 66.667 ms 后，其物理高度已超过当前邻近档案的保守遮挡门槛。

1920 × 1080 下，原抽取快于原详情镜头的早期跟随。端口在 **216.667–1050.000 ms** 之间不满足全部四角的安全画幅条件，随后稳定回到画幅内。因此，不能把“首次看见端口”当作可冻结原镜头的依据。

本次复现准确重现了旧门槛的数值反例：

- 旧 `lift > 3.25 && detail > .62` 门槛在 **716.667 ms** 通过。
- 此时 lift 为 **3.328542**，detail 为 **0.627662**。
- 实体端口中心为 **(879.025, −73.868) px**，已经位于画面上方。
- 新门槛继续保留原详情镜头，直到 **3366.667 ms** 才接管。
- 新接管时端口中心为 **(782.011, 272.721) px**。

390 × 780 的同一原生路径中，端口一直满足安全画幅条件，但旧门槛通过时相机仍在大幅运动。其最终接管时刻仍由镜头收束决定，不能因端口已经在屏内而提前冻结。

## 各门槛何时稳定通过

以下为默认阵列、60 Hz。画幅栏表示最后一次不满足条件之后重新稳定进入的时间。

| 条件 | 1920 × 1080 | 390 × 780 |
|---|---:|---:|
| 所有口径四角稳定在安全画幅内 | 1050.000 ms | 初始即满足 |
| lift ≥ 4.04 | 1933.333 ms | 1933.333 ms |
| detail > .997 | 2450.000 ms | 2450.000 ms |
| FOV 速度 < .02°/s | 2866.667 ms | 3083.333 ms |
| 相机归一化速度 < .025/s | 3316.667 ms | 3033.333 ms |
| 相机归一化目标残差 < .004 | 3366.667 ms | 3083.333 ms |

横屏最后一帧前，3350.000 ms 的相机残差仍为 **0.004159722**；下一帧降至 **0.003970210**。此时相机速度为 **0.021689857/s**，FOV 速度为 **0.004857151°/s**，其他条件已经通过。

竖屏在 3066.667 ms 的残差为 **0.004102501**，FOV 速度为 **0.020646879°/s**；3083.333 ms 分别降至 **0.003915669**、**0.019715487°/s**，两个门槛同时通过。

因此，默认阵列确实保留了约 0.6–0.9 秒的详情镜头收束尾段。该尾段来自明确的相机稳定条件，没有额外定时等待器。本轮决定保留这些阈值，不用未经实机验证的放宽来换取更早接管。

## 读取入口的旋转长尾

在已稳定的读取镜头中，相机与 lift 一开始就满足条件，等待由原生旋转阻尼控制：

```text
rotation(t) = rotation(0) × exp(−2.8 × t)
```

从 ±0.8 rad 到 0.002 rad 的连续时间为约 **2139.809 ms**，60 Hz 检查在 **2150.000 ms** 通过。从 π rad 起步的连续时间为约 **2628.335 ms**，检查在 **2633.333 ms** 通过。

该段保持原姿态连续，取消时恢复先前目标角。180° 压力样本在约 483–500 ms 已经恢复正面可见，但仍等待原阻尼收束到规定角度，避免成像开始后实体继续明显转动。

## 帧率敏感性

| 默认阵列 | 30 Hz | 60 Hz | 144 Hz |
|---|---:|---:|---:|
| 1920 × 1080 | 3366.667 ms | 3366.667 ms | 3381.944 ms |
| 390 × 780 | 3100.000 ms | 3083.333 ms | 3090.278 ms |

差异来自原有“先更新目标，再指数跟随”的离散步进与阈值检查时点，量级为一个普通呈现帧。没有观察到随刷新率扩大到数百毫秒的额外等待。
